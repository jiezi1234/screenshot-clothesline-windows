# 图片堆叠与悬停突出

v0.15.0，2026-10-28。依据本项目需求独立实现，不参考已有 Windows 移植项目。

## 行为

- 少量图片保持分开；数量增加时先压缩间距，再逐步部分重叠。普通卡片最多重叠约 40%，每张保留可见区域，不缩小图片来塞满整行。
- 鼠标进入露出的图片区域时，该卡片置于最前，放大约 6%，略微上提，边框加深。沿用 100 ms 输入检查周期，出现动画约 150 ms；移开后恢复原大小和层次。
- 保留两段预览：先在绳上突出，继续停留约 400 ms 后显示完整等比大图。大图位置避开放大的卡片和整行，空间不足时向下安排。Esc 收起旁边的大图；绳上卡片保持可操作。
- 突出的图片仍可复制、打开、长按、右键和取下。按下鼠标后保持位置，进入拖动时恢复普通尺寸，并按缩放比例换算抓取位置。
- 相邻图片仍保留可选区域；移到它们露出的部分即可切换。离开整行、翻页、改变大小、收起、锁屏或退出时清理突出状态。
- 录像卡片参与堆叠和绳上突出，继续使用已有播放入口，不触发图片大图解码或视频编辑。
- 超过一页的图片仍可滚轮翻页；拖动到左右边缘停留仍可跨页。末页只有一张时不使用堆叠突出。
- 自动容量沿用按当前屏幕和卡片大小计算的规则，现在使用堆叠后的每页容量；固定 25/50/100 项、超容量转历史和文件保留规则继续生效。
- “减少动画”和系统动画关闭时，突出效果立即切换，停止已有动画。

## 实现

布局由 `DesktopGeometry.Cards` 统一提供，普通排布、容量、分页、插入位置及拖动预览共用同一组位置。最小步长为卡片宽度的 60%；未达到拥挤阈值时保留原卡片尺寸与间距。放大边界被限制在显示器工作区内，兼容负坐标。

悬停通过原生 `WindowFromPoint` 命中真正可见的卡片，放大后使用实际窗口边界定位第二段大图。恢复时只将原卡片放回下一个兄弟窗口之后，不抬高整行，因此不会越过遮挡它的其他窗口。全部位置和层次操作不激活窗口。拖动快照每帧按当前顺序分配层次，手持卡片始终位于快照最前。

未新增运行时依赖、数据库迁移、快捷键或设置项。排序仍写入既有 v3 数据库，悬停只改变显示，不修改文件或排序。

平台参考：[Microsoft SetWindowPos](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowpos)。

## 待人工核验

- [ ] 卡片先突出，稍后显示完整大图；移开、Esc、点击及拖动的收起时机符合预期。
- [ ] 从突出卡片开始排序、反向拖动、拖出保存、Esc 取消和跨页拖动正常，文件及卡片保留。
- [ ] 对突出卡片进行单击、双击、长按、右键和取下，确认操作对象正确。
- [ ] 切换三档卡片大小、减少动画；在实际混合 DPI、多屏、锁屏恢复后检查位置和窗口残留。
